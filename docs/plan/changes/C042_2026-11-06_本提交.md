## 为什么退役而不是「明确它只管非光谱文件」

逐个查了它还在被谁用：

| 东西 | 实际情况 |
|---|---|
| 跑一个 skill（`/api/skills/run`） | **界面上没有入口**，前端那个方法零调用 |
| skill 推荐（`/api/skills/suggest`）、规则引擎认文件（`/api/assist/inspect`）、对着文件问一句（`/api/assist/ask`） | 同上，零调用 |
| 内置的三个 skill | 两个是永远「待接入」的空壳（膜厚 / 光谱早已由模块实现），一个表格预览 |
| 设置页的 Skill 清单、侧栏「3 个 Skill」 | 只是展示，点不出任何东西 |

也就是说它在界面上已经是死的，留着只会让同事拿到两份契约文档、不知道照哪份写。

## 做了什么

**删掉**：`app/skills/`（契约、注册表、执行器、两个适配器、三个内置 skill）、`app/api/skills.py`、
`app/ai/rules.py`（规则引擎只服务 skill 推荐和那两个没有入口的接口）、`/api/assist/inspect` 和 `/ask`、
`docs/SKILL_CONTRACT.md`、`tests/test_skills.py`、前端对应的 API 方法和设置页 Skill 一节。

**留下并搬家**（还在用的）：
- 从任意路径导入 `.py` 的加载器 → `app/modules/registry.py`（模块靠它加载）
- 运行详情 / 最近运行的查询 → `app/storage/results.py`（`/api/runs/{id}`、总览用它）
- `/api/assist/status`（AI 抽屉和 ⓘ 靠它判断模型配好没有）

**对已有用户如实交代**：`workspace/skills/` 里还有旧 skill 时 ——
启动日志里写一条警告；`/api/health` 带回 `legacy_skills`；设置页出现「旧的 Skill」一节，
列出名字、说明已不再加载、指向 `MODULE_AUTHORING.md`。**那些文件夹原样留着，不删。**
工作区不再自动创建空的 `skills/` 目录。

**界面和文档**：侧栏改成「本地服务正常 · N 个功能模块」；README 第六节改成写一个模块（示例代码用平台自己的验证器跑过、通过）；
总览页、模块代码、provider 的说明文字同步改。数据库里 `analysis_run.skill_id`、`key_result.source='skill'` 这两个**列名**不改 ——
它们现在的意思是「哪个处理器」，改名要做迁移，换不来任何东西。
