## 做了什么

### 新的网关层 `app/ai/gateway.py`
AI 助手、智能体、设置页的测试原来各自直接用 httpx 发 OpenAI 格式的请求；现在都经过这一层：
- **两种协议**：provider 的 `api` 字段 = `openai-completions`（原来唯一的）或 `anthropic-messages`。
  Anthropic 走 `/v1/messages`、`x-api-key` + `anthropic-version` 头、system 单列、相邻同角色消息合并；地址写到 `/v1` 也认
- **退避重试**：429 / 502 / 503 / 504 按 1、2、4 秒重试三次，认 `Retry-After`（最多 30 秒）；500 不重试
- **思考参数**：按模型名认是哪一派（Qwen3 → `chat_template_kwargs.enable_thinking`，DeepSeek-V4 / Kimi-K2 → `chat_template_kwargs.thinking`，
  GLM-5 → `enable_thinking`，GLM-4.x → `thinking.type`，Claude → `thinking` + 预算，OpenAI 推理模型 → `reasoning_effort`）。
  **缺省显式关**（IFlow 在内网网关上实测：开着会把输出吞掉或挂住）；只回了思考、正文为空时报「把思考关掉」
- **拒收降级**：网关 400 / 422 拒收时先摘思考参数、再退回整包，并记住这个网关 × 模型；网关不认 `tools` 时交给智能体退到动作协议，不误记成思考被拒
- **流式**：OpenAI 的 `tool_calls` 按 index、Anthropic 的 `tool_use` 按 content block 一截一截拼；思考内容不进正文；流里的 `error` 帧变成可读的错误
- **拉列表、测速**：Anthropic 的列表是 `/v1/models`；「同一家族只留最新版本」（IFlow 的规则）；单个模型打一句「回复 ok」量延迟，测不通也是一条结果
- **主机白名单**（可选）：`HTE_LLM_ALLOWED_HOSTS`

### 用上它的地方
- `OpenAICompatProvider`（名字没改，现在两种协议都接）：`chat` / `chat_stream` 都走网关层 → **AI 助手和 ⓘ 提问直接能用 Anthropic 协议**
- 智能体驱动：Anthropic 下工具是 `input_schema`、调用是 `tool_use`、结果是 `tool_result`（多条并进同一条 user 消息）
- 设置接口：`/models/simple` 收 `api` 和 `thinking`（不给就沿用）；`/models/discover` 按协议拉列表，另给一份去重后的测速候选；
  新增 `/models/test-one`（单个模型测速，密钥留空用已存的那把，只认合法模型名）
- 预设：加了通义（DashScope）和 Anthropic，带协议和模型提示；选预设会顺手把协议填上

### 设置页
- 「协议」下拉（OpenAI 兼容 / Anthropic）、「思考」下拉（关 · 推荐 / 开 / 不发参数）
- 「获取可用模型」改成 **「拉取并测速」**：拉回列表立刻显示，再并发 3 个逐个测，边测边显示延迟，可以「停止测速」；
  同一家族的旧版本标「没测」；测完通的按延迟排前面，不通的划掉沉底
- 已配置的表上多一列「协议 · 思考」
