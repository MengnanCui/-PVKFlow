## 做了什么

### CI（`.github/workflows/ci.yml`），每次推送都跑
| 任务 | 内容 |
|---|---|
| lint | ruff（规则见下） |
| test | pytest：Ubuntu × Python 3.11 / 3.13、Windows × 3.11；装 node 跑算子一致性和前端打包检查 |
| startup-windows | **真的跑 run.bat**：建虚拟环境、装依赖、起服务，打健康检查、首页、前端脚本 |
| startup-linux | 同上，跑 run.sh |

### ruff
- 进 `requirements-dev.txt`（钉 0.17.4），规则写在 `pyproject.toml`：只开抓 bug 的 —— 语法错误、pyflakes、bugbear
- 第一次跑就抓到 **1 个真缺陷**：`app/storage/naming.py` 用了 `Any` 却没导入（有 `from __future__ import annotations` 所以运行时没炸）
- 还有我自己上一轮留下的 2 处：`_store_copy` 的 lambda 抓了循环变量（立刻调用所以没出事，绑成默认参数）
- 其余是清理：30 个未用的 import、几个算了不用的变量、一行两句

### 补测试缺口
- `tests/test_module_api.py`（13 条）：装（两种 zip 结构）→ 列表 → 导出 → 卸载往返；验证不过不留痕（暂存区也清干净）；
  **zip 里 `../` 指向目录外的路径被拒、外面没有写出文件**；坏 zip / 空 zip / 多个顶层目录 / 没有 module.py；
  超大 zip；内置模块不能卸；计算接口返回全部面板、模块崩了说清是哪个模块、不存在的模块 404
- `tests/test_frontend_bundle.py`（2 条）：前端没有构建链，借离线烤制的打包器检查「只有两种 import、没有 default export、依赖无环」，
  再用 node 做语法检查 —— 写错一个括号或写出一个 import 环，CI 当场红
