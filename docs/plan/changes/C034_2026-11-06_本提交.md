## 做了什么

### #2 关键结果的当前值
`key_result` 只追加，每跑一次批处理每个样品就再多一整套字段；原来 AI 上下文、按字段筛选、字段列表都直接读整张表。
**复现**：旧一次 9000、新一次 1000，AI 拿到的是 9000。

- `schema.sql` 新增视图 `key_result_current`：同一个 (样品, 字段) 里最后写入、且没被作废的那一条
- 改读当前值的：AI 逐样品标量、按字段筛选、字段分面、字段列表、样品的结果数、总览计数、`/api/results` 默认
- 继续读全部历史的：某一次运行自己的结果（对比页、运行详情）；`/api/results?history=true`

### #3 去重第 ③ 条只认真正的「测量文件夹」
原来对所有文件按相对路径比：两个主文件夹下各有一个 `film.csv`（内容不同），第二个被当成「同一个文件夹」静默丢掉。
- 第 ③ 条只在**文件夹名里带仪器测量时刻**（如 `ZG0013_2026072918354709_…`）时才判 —— 那样的名字一次测量一个
- `sample1/Data.csv`、`film.csv` 这类名字不承担测量身份，只按内容和绝对路径去重
- 你在 C017 要的那条仍然成立：同一次测量重新导出、甚至换了个主文件夹放，照样判重复；理由文字改为「同一次测量的文件夹」

### #8 默认配方只剩一份
原来后端 `Recipe` 写死 780–1050（规范 DEFAULTS），前端两处各写 775–1120 和积分 / 斜率默认值。
- `Recipe` 的六个扁平字段默认「没给」，构造时从已装模块的控件声明里取：膜厚 775–1120（P-05）、积分 800–950、斜率 950 ± 10（P-40）
- 取不到（内置模块没加载上）就报错说清楚，不拿写死的数顶上
- `/api/batch/preview` 带回 `recipe_defaults`，AI 卡片打开的批处理对话框从这里预填；「对比选中」直接发空配方
- `process.js` 里的 `DEFAULT_RECIPE` 和对话框里那份内联默认值删掉

### #10 长表的文本列按文本读
pyarrow 没装时长表是 CSV（默认路径），原来 `pd.read_csv` 不指定类型：样品名 `001` 变 1、空批次变 NaN，图例出 `nan/1`。
- 新增 `tabular.read_frame()`：`sample_id / sample_name / batch / label / group` 按文本读，数值列的空仍是缺失
- 对比页曲线 / 切片 / 导出、`/api/tables` 都走它；导出的 `plot.py` 读 `data.csv` 时同样按文本读

- P-05 膜厚窗口 775–1120、P-40 特殊处理默认值 —— 现在是唯一来源（模块声明）

## 我自行决定的
- **D-47** 「当前值」的定义：最后写入且未作废；作废最新则退回上一条。不同参数跑出的结果也是「最后一次为准」（建议你确认）
- **D-48** `/api/results` 默认只给当前值（它目前没有界面调用方，构效关系页会用它）；总览的「关键结果」「待复核」改按当前值计数 —— 数字会比原来小
- **D-49** 去重③只对「文件夹名带测量时刻」的生效；判据是 `naming.parse_run_folder` 能解析出时间戳（建议你确认）
- **D-50** 默认配方的唯一来源 = 模块控件声明；缺模块时报错不兜底
- **D-51** CSV 长表里哪几列算文本：`sample_id / sample_name / batch / label / group`
