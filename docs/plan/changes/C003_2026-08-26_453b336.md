## 当时的说明（原文）

一次只能看一个样品的时候，样品列表点一下就够了。要一批一批地做，
点不动了 —— 而且 1000 个 ID 放不进 URL，一周后也看不出当初选了什么。

**一次选择 = 一个可见、可改、可保存的筛选式。** 这个决定同时解决三件事：
可复现、可分享、新导入的样品能自动进来。

选择（app/storage/selection.py）
  分面筛选（批次 / 文件夹 / 方法 / 导入批次 / 数值区间），面内是「或」跨面是「且」，
  每个分面带实时计数，且计数排除自己那一维 —— 否则点完一个选项其余全变 0。
  名字里可枚举的那一段自动认出来渲染成双端滑块：范围不用去别处读，
  范围本身就画在那里。手点两三个之后，平台算出共同点主动提议扩展成规则。
  样品集分动态（存筛选式，新数据自动进）和固定（存 ID 快照，论文图必须钉死）。

执行（app/tasks.py / app/batch.py）
  单样品页那套参数就是配方，不做第二套表单。1000 个样品 × 1 秒 = 17 分钟，
  同步请求必然超时，所以走后台任务 + 轮询进度，可取消。
  父运行记配方和筛选式，每个样品一条子运行 —— 上千个样品里一定有跑失败的，
  你必须知道是哪些、为什么，一条大记录说不清楚。
  曲线合成一张长表 Parquet（加样品就是加行），标量进 key_result，
  构效关系页立刻有东西可用。

出图（app/plotting/script_export.py）
  超过 60 条自动降级成中位数 + 四分位带并在图注写明 —— 降级是标出来的，不是偷偷少画。
  导出 plot.py + data.csv + README：平台内置图型不够用时你拿脚本走人随便改，
  而且论文里那张图是你自己能读能改能引用的代码画的。不执行模型写的代码。

一路上撞出来的三个坑，都留了回归测试：
  · 样品身份是 (名字, 批次)。命名规则把 B20_S1 拆成 batch=B20/sample=S1，
    S1 在每个批次里都有一个 —— 只按名字唯一会把 12 个批次的 S1 静默合并成一个。
    240 个文件只建出 20 个样品，小数据集上根本看不出来。
  · 导出脚本按 sample_name 分组犯的是同一个错：B20/S1 和 B21/S1 会被合成一条曲线，
    图少一条，而且那条曲线里两个样品的时间轴是交错的。改成按 sample_id 分。
  · 中文标签在没装中文字体的机器上画出一排豆腐块，matplotlib 只 warn 不报错，
    只看返回码发现不了。脚本自己挑字体，一个都没有就退回英文标签。
    测试里断言 stderr 没有 missing-from-font。

千级规模的实测（都是跑出来的，不是估的）：
  筛选查询 4.5ms（原来 213ms，改成真列 is_matrix + 补索引 + 三个子查询合并成一个 JOIN），
  分面计数 12ms，批处理冷 108ms/样品、热 5ms，240 个样品 13.1s，
  长表 48240 行 0.59MB。

134 个测试通过，包含真的把导出的 plot.py 执行一遍、确认出图且是 300 dpi。
