## 做了什么
**过渡**（`web/css/components.css` 末尾「动效」一节；`web/js/app.js` 写方向）
- **切页**按方向动：点进下钻页（样品、批处理结果、QFLS 样点）新页从右边推进来；按「返回」或浏览器后退从左边回来；
  侧栏之间换页从下面浮上来、带一点点缩放（像从后面浮到前面）
- **弹窗**：遮罩从透明暗下去（背后的页面「退到后面」），窗口从下面滑上来、从 0.965 放大到原大，末尾轻轻落位；关的时候反过来、更快。
  关的那一刻类名就换掉（`.modal` → `.modal-leaving`），所以键盘、「再开一个」、测试脚本都不会碰到正在退场的那个
- **AI 抽屉**从右边滑进来（铺满屏时从下面浮上来）；ⓘ 浮层、菜单弹出来；右下角提示从右边滑进来；按钮、导航项按住时缩一点点
- **初始速度变化**：进场都用 expo-out 缓动 —— 起步最快、越来越慢地收住；弹窗末尾带 1.04 的轻过冲（落位时「弹」一下，看不出在晃）；
  退场反过来先加速走开。进场 260–320 ms，退场 150 ms（出现时你在看它，消失时你已经在看下一样了）
- 系统设了「减少动态效果」：全部关掉（实测动画时长 0.00001 s）

**试过、没用的两样**（都是实测出来的，见验证）
- 浏览器的 View Transitions（旧页、新页各拍一张一起动，旧页同时退后变暗）—— 切页 p95 帧时间从 17 ms 涨到 83–100 ms：它要把整个主区拍成图再合成
- 弹窗背景模糊（backdrop-filter）—— 开弹窗 p95 帧时间 67–83 ms。只留变暗，回到 17 ms

**速度**
- **「当前值」整表汇总快 15–25 倍**：字段清单、总览计数、分面的字段范围原来每一行都去查一遍「同一格最大的 id」，
  55 个样品就要 40–75 ms、随批处理次数线性变慢。加了第二个写法 `key_result_current_all`（先分组再连回来）只给整表汇总用，
  逐样品的查询仍用原来那个（新写法放进逐样品子查询里会到 9 秒）。两个视图逐行相同（新测试守着，含作废、无样品的结果）。
  样品列表里「几条关键结果」换成「有没作废值的字段数」（同一个口径，不用逐行找最大 id）
- **模块计算结果缓存**：样品页每进一次都把膜厚全分辨率算一遍（服务端 330 ms，算法本身冻结不动）。同一份文件（按内容 sha256）、
  同一套参数结果永远一样 —— 现在第二次直接给（20 ms）。模块重新加载（装 / 卸 / 升级 / 改代码重载）就整个清空
- **再进一页不闪骨架屏**：旧内容先留着、顶上一条细线说「在刷新」，新数据到了原地换掉；400 ms 还没回来才换成骨架屏

## 用户明确指定的参数
- **P-59** 页面点击后有过渡；窗口滑动出现，有初始速度变化、有页面深浅变化；优化操作速度；查之后可能的问题

## 我自行决定的
- **D-200** 动效的具体数（时长、位移、缩放、缓动曲线）；只动 transform / opacity；不用 View Transitions 和背景模糊（实测掉帧）
- **D-201** 再进一页旧内容先留着，400 ms 后才换骨架屏
- **D-202** 模块结果缓存 64 份、钥匙和清空时机
- **D-203** 「当前值」两个写法、各用各的

都不影响任何数值或科学结论（缓存的是同一个算法对同一份数据同一套参数的输出；两个视图逐行相同）。
