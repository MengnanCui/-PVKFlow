## 当时的说明（原文）

验收线是「平台最难的那块也能用这套契约表达出来」。迁得动，契约才算够用。

契约扩了四样，**全部可选，简单的写法一个字没变**：
- 多序列：Series(x, y, label, style, color)。颜色只收语义名
  （ok/warn/danger/muted/accent），不收十六进制 —— 收了调色板就守不住
- 三种面板：xy（默认）/ heatmap（服务端位图 + 矢量轴）/ text（整幅宽等宽块）
- 图注与提示：Stat（带 ⓘ 的数字）/ Notice（面板级提示块）/
  info_extra（跟着当前数据走的 ⓘ 附加段）
- 批处理：Curve(key=) 从 PanelData.batch_extra 取不画在图上的列；
  ModuleSpec.batch_all_frames 声明这个模块不接受 max_time_points 抽稀

膜厚整块迁成 app/modules/builtin/thickness/：5 个面板、B 档、
算法全部来自 fringe_ot（一个字不改，DEFAULTS 不动，平台值仍走显式 override）。
sample.js 少了 245 行，膜厚的界面代码归零。

顺带收掉那处重复：批处理里手写的那段 FFT 删了，膜厚只在模块里算一次。
判级不再是 status 字符串列，改成模块算的 ot_ok 0/1 列，/slices 从它取可信比例。
有测试断言 app/batch.py 里不再出现 extract_series。

本地验证 python -m app.modules.check 我的模块/：和界面导入走同一份代码、
同一份文案（有测试逐字断言），退出码 0/1。改一行到看见报错从一分钟压到一秒 ——
那个循环快不快，直接决定同事的模型能不能收敛。

顺手修的三个真问题：
- 提示块画到图下面。画上面会把这一格顶下去，同排另一格没有提示块，
  两张图的顶就错开一百多像素
- ctx.needs() 跳过的面板不再被清成骨架屏。省 165 ms 不该以少一张图为代价
- image_url() 的取值当场校验。cmap 写错原来只在页面上出一个红框
  「HTTP 422」，现在装之前就说清能写哪几个。白名单从 render.py 取，不抄第二份

实测（同一台机器、同一份真实数据）：
- 膜厚 松手 → 曲线更新    迁移前 50 ms   迁移后 48–55 ms
- 特殊处理 拖动 → 曲线更新 迁移前 2.2 ms  现在 2.4 ms
- 逐点一致：OT 最大差 5e-4 nm（可测下限 2275 nm），可信帧 75/211 两边相同
- 规范报告 346 行 / 211 帧逐行，与迁移前逐字相同
- 四宫格图顶对齐 153/153、645/645，功能区等高 43/43、55/55

330 项测试通过。
