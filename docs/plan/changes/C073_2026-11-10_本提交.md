## 做了什么
- **`app/util/`（新）**，全平台共用的小工具只留一份：
  - `files.py` 原子写（`atomic_write_with / _bytes / _text / _json`）：原来 4 份（QFLS 的 run.json、智能体改文件、导入复制、解析缓存）各写各的，
    **存模型密钥的 `providers.json` 反而不是原子写**（存到一半断电，所有模型配置一起没了）—— 现在全走这一份
  - `text.py` 字节 → 文本（先认 UTF-16，再 UTF-8 / GB18030，latin-1 兜底）：原来解析器、QFLS 的 qvdf、智能体跑命令的输出各一份，
    规则不一样（qvdf 那份不认 UTF-16，命令输出那份靠系统编码）
  - `csvsafe.py` CSV 防公式：原来放在「导出绘图脚本」的模块里，QFLS 和批处理都要跨模块去拿
  - `ids.py` 时间戳和 id（见下）
  老位置（`sniff.decode_bytes`、`script_export.guard_formula`、`db.now / new_id`）照旧能 import，转到新地方
- **`app/errors.py` 的 `NotFound`**：领域层「找不到」一律抛它（14 处）；接口层只把它翻成 404。
  **普通的 KeyError / TypeError 不再被当成 404 / 400** —— 那多半是程序 bug，原来会显示成「没有这个：xxx」把 bug 藏住；现在报 500 并记日志。
  NotFound 是 KeyError 的子类，老的 `except KeyError` 照样接得住
- **时间与 id 一种写法**（`app/util/ids.py`）：时间戳一律 UTC（`+00:00`）—— QFLS 的 run.json、智能体事件、迁移记录原来是不带时区的本地时间；
  测量时间是唯一例外（仪器的本地时钟）。可排序的 id 一种格式 `前缀_UTC时间_6位hex`（QFLS 处理编号 `qr_…`、智能体文件改动 `chg_…`），
  原来文件改动的编号是没有前缀的 `日期-hex`
- 迁移的「列不存在就补」合成一个 `add_columns()`（第 1、4 步原来各写一遍）
