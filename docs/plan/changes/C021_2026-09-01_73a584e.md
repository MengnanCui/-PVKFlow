## 当时的说明（原文）

实测发现的：鼠标在图上每移动一次，chart.js 的 draw() 第一行就把整张 SVG
拆了重建 —— 网格、坐标轴、每条曲线的 path 字符串、散点、图例。而 draw()
就挂在 mousemove 上，没有 rAF 合并。热力图更狠：连位图那个 <image> 节点
都重建，所以正在悬停的节点被悬停这个动作本身换掉了。

改法是把图分成两层：
- 骨架（网格/轴/曲线/散点）——只在数据、缩放视窗变了才重画
- 浮层（十字线/读数框/框选矩形）——常驻一个 <g>，跟着指针走
指针事件用 rAF 合并，写法和 virtual-list.js 里那个一致。

实测（同一台机器，同一把尺子；阻塞 = 一次指针事件占住主线程多久）：

  条数×点数     阻塞中位          新建节点/次
   1 × 600    0.8 →  0.1 ms      48 →  7
   3 × 600    1.2 →  0.1 ms      59 → 13
  14 × 600    3.2 →  0.1 ms     100 → 29
  60 × 600   17.5 →  0.1 ms     287 → 29

60 条那一档原来一个鼠标事件就要 17.5 ms（p95 72 ms），16.7 ms 的帧预算
一次就花光了。现在 0.1 ms。

页面内实跑：膜厚 OT 曲线 1.4 → 0.1 ms（260 → 11 节点），
热力图 0.7 → 0.1 ms（40 → 5 节点）。

顺带修掉三个真问题：
- 60 条曲线时读数框有 858px 高，比图还高，等于把图整个盖住。现在最多列
  8 条并说明「还有 N 条」，而且按到指针的竖直距离排序 —— 列出来的是你
  光标底下那几条，不是碰巧排在数组前面的
- 同页多张图时 clipPath 和色标渐变的 id 会撞，后挂载的把先挂载的裁坏
- 分面板搜索框每次筛选都被重建，焦点和光标一起丢。现在节点常驻，
  mount 之后把焦点和选区放回去（移动一个带焦点的元素会让它失焦）

没有退步：拖动 → 曲线更新，原始代码 3.3/3.3/3.6 ms，新代码 3.2/3.2/3.2 ms
（同一台机器同一时刻对照跑的；仓库里记的 2.2 ms 是更早在更闲的机器上量的，
这台机器新旧两版都是 3.3 ms）。膜厚松手 → 曲线更新同样无差别。
图表交互 18 项、热力图 11 项、换色标/换归一化 8 项，逐项实操验证通过。
330 项 pytest 全绿。
