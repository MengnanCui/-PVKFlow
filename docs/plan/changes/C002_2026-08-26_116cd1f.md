## 当时的说明（原文）

导航压成两层：数据处理页顶部是四个子功能（吸收光谱&膜厚可用，其余三个
如实标"规划中"），下面直接是样品列表，点一次进样品详情。

样品详情三个模块
  光谱处理  波长-时间强度热力图 + 归一化强度 vs 波长多时刻叠加
  膜厚处理  波数-时间干涉条纹图（全波段 + 可调波段），OT 曲线留接口占位
  特殊处理  某波长谱斜率、某波段积分，拖滑块实时更新

图怎么画：位图归位图，曲线归曲线
  热力图 10⁶ 像素在服务端渲染成 PNG（0.15–0.35 MB），坐标轴是矢量的。
  10⁶ 个 SVG 矩形会卡死浏览器；用 canvas 则要传 3.6–25 MB 矩阵。
  曲线全部前端 SVG，可悬停、可框选、跟随明暗主题。

中间数据集：一份数据喂三张图
  抽样谱自适应控制在约 1 MB，走二进制而非 JSON（6.7 MB → 0.90 MB，37 ms）。
  前端拿到后换时刻/波段/波长全部本地完成：积分 0.16 ms、斜率 0.03 ms，
  拖动 31 步 42 ms。停手 0.3 秒后自动取后端全分辨率结果替换，界面标注
  当前看的是"实时预览"还是"全分辨率"。抽样偏差实测 0.02%（积分）～1.6%（斜率）。

三条硬约束
  膜厚 FFT 只在后端做 —— 同一段物理两份实现，漂移了就分不清该信哪个数。
  降采样用面积平均不用抽点 —— 条纹是高频信号，抽点会造出数据里没有的摩尔纹。
  色标亮度必须单调 —— 否则数值不同的区域看起来一样亮，有测试守着。

顺带修的
  通用嗅探器被文件头 # 注释行带偏，分隔符判成空格。仪器导出普遍有抬头，
  这个 bug 影响的不只是矩阵解析。
  图表刻度 -100 被去尾零正则削成 -1。
  波数重采样逐列 np.interp 350ms → 向量化 10ms，偏差 1e-7。
  PNG optimize=True 花 8 倍时间换 2% 体积；先缩放灰度再上色，1243ms → 136ms。

npz 缓存让重复打开从 890ms 降到 20ms，内容寻址天然失效不用写逻辑。
25 个新测试覆盖判向、缓存、重采样等价性、降采样、色标亮度、API 错误结构。
