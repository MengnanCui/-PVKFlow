## 1. 「是不是光谱矩阵」只剩一份判断

原来有三份：

| 在哪 | 什么时候用 | 规则 |
|---|---|---|
| `ingest._mark_matrix` | 导入时 | 先认原位 Data.csv 格式，不是再数列数 ≥ 8 |
| `spectra._probe_and_remember` | 列样品时，碰到还没判过的老数据 | **只数列数 ≥ 8，不认原位格式** |
| `matrix.looks_like_matrix` | 没人调用 | 只看前 8 行数列数 |

两条在用的路规则不一样：**时间点少于 7 个的原位文件只有 7 列，导入时说是矩阵，惰性那条路说不是**（写测试复现了：旧代码上 `with_matrix` 是 0）。
在样例数据上两条路碰巧一致（都是 212 列），所以一直没露出来。

现在：`matrix.probe()` 一份判断（只读文件头），`ingest.mark_matrix()` 一份写库，导入和惰性补判都走它。没人调用的那份删了。

**顺带**：判断原位格式的 `looks_like_insitu` 原来为了看前 400 行把整个文件读进来（真文件 2.3 MB），每导入一个文件读一遍。
改成只读前 512 KB（截在最后一个换行处再解码 —— 截在多字节字符中间会让编码判断退到别的编码上），并且认出来就停。
实测同一个文件 **18.3 ms → 4.3 ms**。结果不会变：判断条件里的几个标记只会从「否」变成「是」，凑齐了就是最终答案。

## 3. CI 第 6 次运行（提交 1b2ec13）

| 任务 | 结果 |
|---|---|
| lint、Ubuntu 3.11 / 3.13、Windows 3.15、run.sh、**run.bat** | ✅ |
| **test · Windows · 3.11** | ❌ 415 通过、2 失败 —— 是我新写的 CSV 测试的毛病，不是产品的 |

CSV 测试用 `text=True` 读 node 的输出：Windows 上按系统编码（cp1252）解码，node 吐的 UTF-8 中文和 BOM 就全乱了。
Windows 3.15 没事，是因为 Python 3.15 起默认就是 UTF-8 模式。
本机用 ASCII 区域设置（`PYTHONUTF8=0 LC_ALL=C`）复现了同样的两条失败；改成明确按 UTF-8 解码后通过。

顺手用这个区域设置把整套测试跑了一遍，看还有没有别处依赖系统编码：其余失败全是「建不了中文名的目录」——
那是 Linux 在 ASCII 区域设置下文件系统编码也变成 ASCII，Windows 的文件系统接口永远是 Unicode，不代表 Windows 的情况。没有别的问题。
