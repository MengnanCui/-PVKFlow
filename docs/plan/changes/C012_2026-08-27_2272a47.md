## 当时的说明（原文）

**图片对齐（4 条）**
`.fig-grid-2/4` 改用 subgrid：每个 .figure 固定成三行（标题 / 功能模块 / 图），
行高由父网格在整行上统一取最大。所以左右两格的标题一条线、图一条线，
哪怕一边有俩滑块另一边什么都没有 —— 那一格就空着。四宫格是两条 3 行的带，
上排自己对齐、下排自己对齐。subgrid 不可用时退回原来的独立布局。

顺带：并排的图里让 .figure-head 贴顶。行高取最大之后矮的那格会被拉伸、
内容垂直居中，于是图对齐了标题反而差 6–8px。

膜厚上排「这一格是对照」那段说明从图上面挪到图下面 —— 放上面它会把
同排的条纹图一起往下推三行，为几行字浪费一整块竖向空间。

**★ 顺手修掉一个 push ③ 带进来的真 bug**
AI 抽屉关着的时候 --ai-w 仍是 380px，第三列一直占着位置：主区被白白切掉
380px，样品页并排的两张图从 1180px 缩到 800px。之前几次截图都开着抽屉，
所以没看出来。initDrawer 里改成先清零。

**下载选项**（新 web/js/download.js）
六张图每张一个「下载 ▾」，两个子项：下载图片 / 下载数据(CSV)。
- SVG 图表就地栅格化成 2× PNG。序列化前要把算好的颜色逐个写死成属性 ——
  图里的颜色全是 var(--s1)，脱离页面就没有值，画出来一片黑。
- 服务端渲染的热力图直接取那张 PNG，不在前端重画。
- CSV：各条曲线共用 x 轴时出宽表，否则出长表。x 不一致还硬凑宽表就得补齐
  或插值，那等于凭空造数。带 BOM，Excel 打开中文列名不乱码。

**时间筛选**
加「选择…」弹窗：原生日历选日期 + 原生 time 选时分，精确到分钟。
手打那条路原样保留。

★ 同时修掉一个语义 bug：「到 18:35」在人话里包含 18:35 这一分钟，但字符串
比较下 "…T18:35:47" <= "…T18:35" 是假的，那一分钟里的测量会被静默排除。
真实数据里同一轮实验几次测量只差几分钟，少掉一整分钟就是少掉一次测量。
上界按用户给的精度补齐（到日补 23:59:59、到分补 :59）。

**删掉「选中分析」建议条**
它挂在列表上方向下弹出，一出现就把样品行推走，正在挑样品时点不中。
后端 /api/selection/suggest 和 selection.suggest_expansion 都留着。

**数据存储页**
加全库搜索（走已有的 /api/selection/query 的 q 键，同时匹配样品号和样品名，
命中截断时明说）；删掉「按类型分布」；页面说明改成写清跟数据处理页的分工。

测试 223 → 225。浏览器实跑验过：三个模块标题与图逐像素对齐（明暗两套）、
报告框半高但可滚且块 A–D 齐全、CSV 宽/长两种形状、PNG 与热力图都真的下得来、
时间弹窗选到分钟且 18:35 那次测量能命中、建议条消失后列表不再被推走、
存储页搜 ZG0014 命中 2 个。
