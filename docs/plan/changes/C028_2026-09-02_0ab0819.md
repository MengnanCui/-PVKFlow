## 当时的说明（原文）

你提的第 5 条。逐页开控制台走了一遍主要路径，加上边界数据、
对比页的五种状态、所有 API 端点的错误分支。找到并修了六条：

**一、每个报错底下都糊着一坨 JSON。** `api.js` 里写的是
`e.detail || text.slice(0, 500)` —— 后端给的 detail 绝大多数是空串，
于是每一个正常报错都会在人话下面再贴一遍
`{"error":{"message":"没有这次批处理：run_x",…}}`：同一句话说两遍，
第二遍还是给机器看的。原始响应体现在**只在看不懂的时候**才当 detail 用
（公司代理的 HTML 登录页、网关自己的 502 —— 那时候它是唯一线索）。

**二、参数不合法时整个平台只有这一处说英语。** FastAPI 默认吐的是 pydantic
的原始结构，前端认不出来，显示成「请求失败（422）」加一坨
`String should match pattern '^(integral|slope|ot)$'`。而这偏偏是
「你哪里填错了」这种最需要说人话的地方。加了 RequestValidationError 处理器，
翻成平台自己那套结构：「column 只能是 integral / slope / ot，给的是 'nope'」
「max_series 要不小于 1」「max_time_points 要是数字」。

**三、`#sample/smp_xxx` 打不开。** 页面地址叫 `sample/`，而界面上能复制到的
id 常常就是 `smp_xxx`（样品列表、失败样品表里显示的都是它）——
原来只收矩阵 id，回一句「文件不存在：smp_xxx」，那句话根本没说到点子上。
现在收样品 id，并回传翻译之后的矩阵 id（不然后面拉热力图、拉帧、
算模块面板每一步都要再翻译一次）。样品存在但没有矩阵和样品压根不存在，
两句话也分开说。

**四、`toast(…, 'danger')` 有四处在用，CSS 里却只有 ok/err/info。**
那四个错误提示弹出来是没有小圆点的（上一个提交里已经补了 toast-danger / warn）。

**五、跑批失败时按钮写着「重试」，点下去却跑到样品列表去了。**
errorBox 的按钮文案现在可传；那一处改成「回到样品列表」。
另外「被取消」不该说成「这次对比没跑成」—— 取消是你自己按的，
说成失败会让人以为出了问题。

**六、柱状图里「一根深色都没有」没人说。** 图注写着「深色那截是其中可信的比例」，
而 18–19 s 那个窗口里一帧都不可信 —— 三根柱子整根是淡的，
看起来只是颜色浅，不像是「这三个数一个都不能用」。现在明写出来。
顺带把 x 轴标签从两行放宽到三行（一格 250px 高装得下三条基线），
每行留 10px 空当 —— 1280 宽下三个标签原来是贴着的。

验证：12 条路由 × 明暗两套 × 两种屏宽扫过，除了故意造的 404 没有 console error，
五档屏宽都不横向滚动；边界数据 4 种（1 个样品 / 时间范围 0.4 s / 整批没数据 /
名字一模一样）、对比页 4 种失败状态、任务 3 种状态，全部无报错；341 项 pytest。
