## 当时的说明（原文）

都是浏览器里真跑出来才看见的，单元测试和小数据集全都测不出来：

· 列表里 24 个批次的 S9 长得一模一样。样品的身份是 (名字, 批次)，
  但 recent_runs 和 artifacts.search 只回了名字 —— 前端拿不到批次，
  再怎么改渲染也显示不出区别。所以是查询的问题，不是渲染的问题。
  两个查询补上 s.batch，加 ui.sampleLabel() 统一显示成 B20/S9。
· 分面里的关键结果字段被截成 "integ…"，integral_initial / integral_final /
  integral_min / integral_max 五行完全一样，等于没写。字段名改成单独占一行。
· 图例里的代表曲线也只写 S1。curves 接口的 label 补上批次。
· 「自动」模式下屏幕已经降级成分位数带了，导出的却还是 90 条叠图 ——
  下载到手的图跟屏幕上看到的不是同一张。抽出 effectiveMode()，
  图和导出共用同一个判断，并在对话框里说明为什么是带。

顺带：分位数带的中位线占了 0 号色，代表曲线也从 0 号开始，
第一条跟中位线同色，图上分不出哪条是统计量哪条是样品。代表曲线整体挪一位。

1200 个样品的实测（合成数据，200×80 矩阵）：
  导入 1200 个文件 1.5s；筛选计数 <1ms，翻页 3.5ms，分面 8.9ms，
  名称枚举段识别 1.3ms；批处理 1200 个 31.1s（26ms/样品），全部成功；
  长表 96000 行 1.19MB，读取 28ms；npz 缓存 1200 个文件 0.08GB。
  浏览器里滚 20 次 1.2s，DOM 里始终只有 147 行。

浏览器端到端（Playwright，明暗两套，无 JS 报错）：
  点三个批次 → 150 个 → 名称滑块收到 S1–S30 → 90 个 → 批处理 → 进度 90/90
  → 结果页自动降级成分位数带并写明「90 条曲线，显示中位数与四分位区间」
  → 导出脚本。导出的 plot.py 在本机真跑过，1200 条曲线 1.3s 出图，300 dpi。
