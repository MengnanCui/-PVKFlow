## 当时的说明（原文）

推送 ③。导航同时重排：对比历史从主线里挪出来，单独成「分析」组。

后端
- conversation / message / ai_pin 三张表。追加到 schema.sql 即可 ——
  init() 每次启动都跑 executescript，DDL 全是 IF NOT EXISTS，不需要迁移
- openai_compat.chat_stream()：同一个 payload，stream: True。
  切帧逻辑抽成 _iter_sse_text 单独可测 —— 各家网关的 SSE 长得都不一样，
  半截 json 崩掉的话用户看到的是整个回答消失，而不是少几个字
- app/api/chat.py：会话 CRUD + SSE 消息流 + 钉住。
  「没配模型」的 501 必须在**开流之前**同步抛：一旦 StreamingResponse
  开始产出，状态码就在路上了，main.py 那个全局异常处理器再也插不上手。
  流中途出的错走 event: error 帧
- app/ai/context.py：模型能看见什么全在这一个文件里定，所以能单独测。
  L1 汇总永远送；样品数 ≤ AI_DETAIL_MAX(40) 才送逐条明细，超了只给汇总
  并明说「请先收窄」。原始光谱矩阵永不入 prompt —— 一个样品 200×2000
  就把本地 27B 的窗口撑爆了

前端
- web/js/components/ai-drawer.js：撑开 .shell 第三列而不是盖住主区
  （盖住的话每问一句都得关掉才能看图）。左缘拖拽改宽 320–720px，
  记 localStorage；⤢ 全屏，Esc 先退全屏再关；⋯ 菜单（新对话 / 历史 /
  重命名 / 导出 md / 全屏 / 删除）
- 数据范围选择器：「选中的 N 个」/「全部命中的 N 个」两档。
  勾了东西默认前者，没勾默认后者；你自己点过之后不再自动跳档
- 动作卡片：模型的 json 渲染成能改能拒绝的 chip。白名单在代码里而不是
  只在提示词里 —— 模型给 ID 列表时那部分直接丢掉。发起处理只是把配方
  预填进对话框，不点不跑
- 钉住：一条回答钉到某次对比。存的是正文快照，删掉对话也带不走它。
  对比页顶部显示，对比历史行尾显示 📌 计数
- web/js/scope.js：process 页和抽屉之间的共享状态，抽屉不去读 process 的私有 S

测试 197 → 223。浏览器实跑验过：流式逐字、停止只停不重发、拖拽改宽刷新后
记得住、全屏进出、范围四种默认行为、卡片应用到筛选面板、钉住闭环、明暗两套。
