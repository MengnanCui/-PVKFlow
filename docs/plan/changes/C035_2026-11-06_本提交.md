## 做了什么

### #9 同事模块的批处理曲线进对比页
原来对比页、曲线接口、导出只认 `integral|slope|ot` 三个写死的列名。同事模块声明的曲线写进了长表，却取不出来。
- 新增 `batch.curve_catalog()`：这次运行的长表里**实际有**哪些曲线列、在哪张表、叫什么（名字和单位取自模块声明）
- 曲线 / 切片 / 导出接口：列名只校验形状，再对照这次运行实际存的列；没有就报错并列出有哪些
- 对比页：平台那三条位置不变；其余能画的曲线各占一格（标题 = 面板标题 + 模块名），先补上「波段积分」旁边原来空着的那一格
- `ot_ok` 这种 0/1 辅助列（`Curve(key=...)`）不单独画

### #11 取消与重启会收尾
**更正审查的说法**：常见路径下旧代码其实能停住（实测取消后算了 5 / 13 个就停了），因为循环开头也查了取消标记。
真正的漏洞更窄，但确实存在：
- **提交后马上取消**（取消信号在第一次报进度时抛出）：父运行永远停在 `running`，任务结果为空 —— 对比历史里多一条永远「运行中」、点进去什么都没有的记录（实测旧代码如此）
- 信号从报进度那一步抛出时会穿过线程池的 `with`，线程池退出时把还没开始的样品全部算完
- 服务重启只改了任务表，分析运行仍是 `running`；提示里写「重新提交会跳过已完成的」，代码里没有这个逻辑

改法：父运行建好之后无论怎么结束都收尾（ok / failed / cancelled）；取消时撤掉还没开始的样品，已跑完的照样进长表（取消是「停在这儿」）；
任务结果带上 `parent_run_id` 和「处理了几个」；重启时把 `running` 的分析运行也标掉；提示改成「重新提交会把整批重新算一遍」。
对比历史每行加状态标签：「已取消 · 只有一部分」「没跑完」「运行中」。

### #12 模块重载原子化、不许顶替内置
- `load_all()` 先装到新容器，最后一次性换上 —— 读的人拿到的要么是旧的一整套，要么是新的一整套
- 同 id 的第二个模块装不上并说清原因（内置先装，所以同事撞 id 时内置的留着）
- 批处理开跑时定下这一批用哪些模块，整批不变

### #13 解析缓存跟着解析器版本走
- `matrix.PARSER_VERSION = 2`，缓存文件名带版本；解析器改了行为就加一
- 旧版本的缓存在淘汰时顺手删掉（再也命中不了）

### #14 原始文件落盘原子化
- 先写同目录临时文件，写完原子换名
- 目标已存在时核对大小，对不上就是上次留下的半截，重写

### #17 结果记下是哪个版本的模块算的
- 父运行的参数里记 `modules: {id: 版本}`
- `key_result.version` = `0.2.0+special.slope_integral@1.0.0,thickness.fringe_ot@1.0.0`（原来永远是 `0.2.0`）

### #24 输入缺失的帧不出假数
- 膜厚模块（平台层）检查窗口内光谱：有 NaN / Inf 的帧，OT 置为「没有数」，判级 `NO_INPUT`（新增说明文字「无数据」），可信标 0
- 时刻平均本来就只算有数的帧；现在少了几帧会写出来：「窗口里有 N 帧没有数（输入缺失），没参与平均」
- 规范的算法 `fringe_ot.extract_series` 一行没动（测试同时断言：直接调算法仍会给一个有限值 —— 拦截确实在平台层）

## 用户明确指定的参数
