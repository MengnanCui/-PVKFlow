## 做了什么
- **`app/api/bodies.py`（新）**：35 个 POST / PATCH 接口的请求体各有一个模型，每个字段写了类型、默认值、一句说明。
  `/api/docs` 和 `docs/REFERENCE.md`（新增「请求体」一节，接口表的「请求体」列链到对应模型）都照它出
- **不认识的键回 400**：「不认识的参数：fitler」。原来拼错一个键静悄悄地被当成没给 —— 比如 `fitler` 拼错，
  选择接口就按「全部样品」算，界面上看不出哪里不对。类型不对也回 400、说中文（「x 要是文本，给的是 ['a']」）
- 路由里的逻辑**一行没改**：第一行 `payload = B.dump(body)` 只留调用方真给了的键，下面照旧。
  有几处靠「给没给这个键」区分「不改」和「清空」（改会话标题 / 范围、改智能体设置），这样才不会被默认值盖掉
- 唯一还收任意键的是 `POST /api/settings`：能改哪些键是运行时决定的（`GET /api/settings` 的 `editable`），路由自己核对，原来就会拒收别的键
- 测试守着：`app/api/` 里除了设置以外不许再出现 `payload: dict = Body`
