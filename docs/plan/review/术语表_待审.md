### 1. 光学厚度 OT　`ot`

- **是什么**：OT = n·d·cosθ，单位 nm。n 是折射率、d 是几何厚度、θ 是光在膜内的传播角。
- **为什么 / 代价**：干涉条纹只能给出这个乘积，给不出 d 本身 —— 要拿到几何厚度，得另外知道该波段的 n。入射角未知时按 θ=0° 处理，所以平台一律只报 OT，**不擅自换算成几何厚度**。

### 2. 条纹数（cycles）　`cycles`

- **是什么**：分析窗口内数得出几个完整的干涉明暗周期。= 窗口的频率跨度 ÷ 一个频率 bin。
- **为什么 / 代价**：这是判断「这一帧的膜厚测得准不准」的唯一硬指标。数得越多，FFT 定峰越准。膜越薄、窗口越窄，条纹数越少 —— 薄到数不出 1.5 个周期时，功率谱上根本没有主峰，argmax 找到的是噪声。
- [ ] 没问题　[ ] 要改：

### 3. 频率 bin　`fringe_bin`

- **是什么**：FFT 在频率轴上的一格。bin = 1 / Δk，Δk 是窗口在 k = 1/λ 上的跨度。
- **为什么 / 代价**：775–1120 nm 这个窗口下，一个 bin 是 2516 nm。窗口越宽 → Δk 越大 → bin 越小 → 同样的膜里数得出的条纹越多、能测的膜越薄。这就是「拓宽窗口」是提升薄膜可测性的**唯一**手段的原因。
- [ ] 没问题　[ ] 要改：

### 4. 可测下限　`ot_floor`

- **是什么**：这个窗口下还能给出可信结果的最小光学厚度 = min_cycles × bin / 2。
- **为什么 / 代价**：低于这个值的膜，窗内条纹数不足 1.5，FFT 会锁到噪声峰上。平台照样把算出来的数字显示出来（判据只打标志、绝不修改数值），但会标成「不可信」—— 你看到的是「算出来是多少 + 为什么不该信」。
- [ ] 没问题　[ ] 要改：

### 5. 量化格距　`ot_quantum`

- **是什么**：补零 FFT 之后，OT 在数值上能分辨的最小台阶 = bin / (2 × 补零倍数)。
- **为什么 / 代价**：曲线上那些小平台不是膜真的停住了，是**数值分辨率的台阶**。想让台阶变细只能加大补零倍数，但那不会增加真实信息 —— 真正的精度上限仍然由条纹数决定。
- [ ] 没问题　[ ] 要改：

### 6. 可信度判级　`ot_status`

- **是什么**：每一帧分三档：可信 / 可用但精度下降 / 不可信。判据是条纹数和信噪比。
- **为什么 / 代价**：**判据只打标志，绝不修改数值。** 不可信的帧照样给数、不置空、不清零 —— 你看到的永远是真实的计算结果加一个「能不能用」的标注，而不是一个被悄悄改过的数。图上标的是**可信**的那一段，因为那才是你要找的东西。
- [ ] 没问题　[ ] 要改：

### 7. 判级：可信　`status:OK`

- **是什么**：窗内条纹数 ≥ 2，且峰值信噪比达标。这一档的光学厚度可以直接用。
- **为什么 / 代价**：门槛定在 2 条纹（规范默认值是 3）：775–1120 nm 窗口下 3 条纹对应 OT ≈ 3774 nm，而真实的钙钛矿湿膜大半段时间到不了 —— 拿 3 卡的话整条曲线几乎全被判成不准，那个标注就失去了区分度。2 条纹对应 OT ≈ 2516 nm，正好落在干燥后期的实际厚度上。
- [ ] 没问题　[ ] 要改：

### 8. 判级：可用但精度下降　`status:DEGRADED`

- **是什么**：条纹数在 1.5 到 2 之间。峰还在、级次也没锁错，但峰形变宽，定峰误差变大。
- **为什么 / 代价**：规范 §4.1 给的实测对照是 cycles 2.37 时偏差 -4.12%。**这一档可以看趋势，不要拿去做定量比较。** 想让它变准，唯一的办法是把分析窗口拓宽。
- [ ] 没问题　[ ] 要改：

### 9. 判级：不可信（条纹不够）　`status:LOW_CYCLES`

- **是什么**：窗内连 1.5 个完整条纹都数不出来。
- **为什么 / 代价**：功率谱上没有真正的主峰，argmax 找到的往往是噪声起伏 —— **算出来的数字和膜厚没有关系**。常见原因：膜已经干到低于可测下限，或者窗口选得太窄。
- [ ] 没问题　[ ] 要改：

### 10. 判级：不可信（信噪比低）　`status:LOW_SNR`

- **是什么**：主峰没有明显高过背景，峰值信噪比低于 4 dB。
- **为什么 / 代价**：常见于信号太弱，或者这一帧本身就没有条纹。
- [ ] 没问题　[ ] 要改：

### 11. 判级：不可信（采样不足）　`status:UNDERSAMPLED`

- **是什么**：平均每个条纹周期上不足 5 个采样点。
- **为什么 / 代价**：条纹本身没被采样清楚，谈不上定峰。
- [ ] 没问题　[ ] 要改：

### 12. 分析波段　`band`

- **是什么**：做 FFT 的波长窗口，默认 775–1120 nm。
- **为什么 / 代价**：775 是为了**避开约 775 nm 的吸收边** —— 规范要求分析波段必须落在膜的透明区，跨过吸收边会把吸收的变化当成干涉的变化。1120 是光谱仪的上限。往右拓宽能降低可测下限，往左会撞上吸收边。
- [ ] 没问题　[ ] 要改：

### 13. 时间点上限　`max_time_points`

- **是什么**：批处理时每个样品最多保留多少个时间点，0 = 全部帧。
- **为什么 / 代价**：一千个样品各两百多帧，长表就是二十多万行 —— 抽稀是为了让它别太大。对逐帧独立的量（波段积分、谱斜率）无所谓：先抽再算和先算再抽结果一样。**膜厚不受它影响** —— 膜厚模块声明了要拿全部帧，它的曲线存在另一张表里，抽稀等于把「哪一秒变坏的」这个答案抹掉。
- [ ] 没问题　[ ] 要改：

### 14. k = 1/λ 轴　`k_axis`

- **是什么**：波数轴。条纹图的纵轴用它，不用波长。
- **为什么 / 代价**：干涉的相位对**波数**是线性的，对波长不是。所以只有画在 k 轴上，条纹才是等周期的 —— 也才能用 FFT 定出那个周期。
- [ ] 没问题　[ ] 要改：

### 15. 归一化方式　`norm`

- **是什么**：热力图的颜色映射怎么定标：每帧 / 每波长 / 全局 / 原始值。
- **为什么 / 代价**：只影响**显示**，不影响任何计算。每帧归一化看单帧内部的形状，全局归一化看不同时刻之间的强度差异。膜厚模块的条纹图不跟这个走 —— 它固定每帧归一化，因为要看的就是每一帧内部的明暗周期。
- [ ] 没问题　[ ] 要改：

### 16. 短波端饱和截断　`saturated_head`

- **是什么**：光谱叠加图默认从某个波长起画，短波端那一截被跳过了。
- **为什么 / 代价**：光源在紫外没有输出，那一段的探测器顶在量程两端。把它算进归一化会把真正的谱压扁到看不见。截断的位置和跳过了多少条波长都写在图注里，滑块也能拉回去 —— **不静默丢数据**。
- [ ] 没问题　[ ] 要改：

### 17. 叠加条数　`overlay_n`

- **是什么**：光谱叠加图上画几条曲线，在选定时间范围内等间隔取。
- **为什么 / 代价**：**纯显示设置。** 它不影响膜厚计算 —— 光学厚度曲线是后端拿完整矩阵（全部波长 × 全部帧）重算的，跟这里画几条没有关系。
- [ ] 没问题　[ ] 要改：

### 18. 谱斜率　`slope`

- **是什么**：在指定波长附近的一个小窗口里，对光谱做线性拟合得到的斜率，随时间画出来。
- **为什么 / 代价**：吸收边附近的斜率对结晶过程敏感 —— 边越陡，说明带边越清晰。窗口太窄会被噪声主导，太宽会把曲率算进去。
- [ ] 没问题　[ ] 要改：

### 19. 波段积分　`integral`

- **是什么**：把指定波段内的光谱强度对波长积分，随时间画出来。
- **为什么 / 代价**：一个对整段透过率的粗粒度概括，抗噪声比单点强得多。终值/初值的比常用来看干燥过程中透过率降了多少。
- [ ] 没问题　[ ] 要改：

### 20. 筛选式　`filter_expr`

- **是什么**：「选中一批样品」在平台里的内部表示：一组条件，不是一串样品 ID。
- **为什么 / 代价**：上千个样品时 ID 列表这个模型直接就是坏的 —— 放不进 URL、一周后看不出当初选了什么、新导入的样品永远进不来。换成筛选式之后：可复现、可分享、能随新数据自动生长。
- [ ] 没问题　[ ] 要改：

### 21. 样品身份　`sample_identity`

- **是什么**：一个子文件夹 = 一次测量 = 一个样品。样品名取完整文件夹名。
- **为什么 / 代价**：同一片样品测两次就是两个样品。只按前缀（比如 ZG0014）认身份的话，两次测量会被静默合并成一次 —— 数据没丢但全串了，而且在小数据集上根本看不出来。做统计时别把它们当重复样平均掉。
- [ ] 没问题　[ ] 要改：

### 22. 导入去重　`dedup`

- **是什么**：三条依次判：内容相同（sha256）、同一个文件、同一个子文件夹。
- **为什么 / 代价**：光靠内容哈希不够 —— 仪器重新导出一次，字节会变、哈希会变，但那还是同一次测量。所以按子文件夹也要挡一道。
- [ ] 没问题　[ ] 要改：

### 23. 落地方式　`storage_mode`

- **是什么**：文本类文件复制进工作区，图像类只登记原始路径。
- **为什么 / 代价**：文本文件小、易丢、经常被人手改，复制一份才谈得上可复现；图像动辄几百 MB，搬一遍不划算。代价：引用型文件被移动或改名后会断链，界面上会标成「丢失」。
- [ ] 没问题　[ ] 要改：

### 24. 分位数带　`quantile_band`

- **是什么**：曲线超过 60 条时，叠图自动降级成中位数线 + 四分位带。
- **为什么 / 代价**：上千条曲线叠在一起是噪声不是图。降级这件事会写在图注里，**不偷偷少画** —— 你随时能切回逐条模式。
- [ ] 没问题　[ ] 要改：

### 25. 功能模块　`module_contract`

- **是什么**：同事往平台里加功能的方式：一个文件夹，里面一个 module.py，声明有哪些控件、哪些图、产出什么。放进工作区、点一下重载就生效。
- **为什么 / 代价**：**他只交算法和声明，界面由平台画。** 所以他加的功能和平台其它部分长得一模一样 —— 面板结构、控件、图注、ⓘ、左右对齐全是平台的组件，他碰不到 CSS，风格想漂也漂不了。分发就是发那个文件夹（或它的 zip），不用 Git、不用分支 —— 这是为网络受限、不会用 Git 的同事设计的。代价：表达力有边界，声明写不出来的东西就得写 Python（松手才算）。
- [ ] 没问题　[ ] 要改：

### 26. 算子　`module_op`

- **是什么**：平台提供的一小组现成运算（波段积分、谱斜率…）。模块引用它们，不实现它们。
- **为什么 / 代价**：每个算子有 JS 和 Python 两份实现：拖控件时跑 JS（本地，2 ms），批处理时跑 Python。有一条测试断言两份**逐点相同** —— 少了它，症状是「界面上拖出来一个数、存进库里是另一个数」，而且没有任何报错。**所以算子集是封闭的**，模块作者不能自己加：加一个要同时写两份实现加一条一致性测试，那是平台维护者的活。
- [ ] 没问题　[ ] 要改：

### 27. AI 数据范围　`ai_scope`
