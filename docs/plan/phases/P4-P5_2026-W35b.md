## P5 · 模块化（08-30，C019–C020）

**起因（你的诉求，P-29）**：同事要能往平台里加功能；担心风格漂、GitHub 用不了、同事只有弱模型。
**硬约束（P-30）**：拖动即时响应不能丢。

**做法**
- 新契约 `app/modules/`：同事交一个 `module.py`（声明 + 可选算法），界面由平台画
- A 档：用平台算子拼（`Op.band_integral` / `Op.wavelength_slope`），拖动时浏览器里跑；
  B 档：自写 Python，松手才算
- 算子集封闭，JS / Python 双实现 + 逐点一致测试（`tests/test_ops.py`）（D-36）
- 验证器即反馈通道：报错点名字段、猜拼错的词；`python -m app.modules.check` 本地一秒出结果
- 分发靠 zip（设置页导入 / 导出），不靠 Git
- 「特殊处理」迁成模块（零算法，纯算子拼）；**膜厚整块迁成模块**（5 个面板，B 档）
- 契约扩展：多序列、三种面板（xy / heatmap / text）、Stat / Notice / info_extra；颜色只收语义名（D-37）
- 批处理改由模块声明驱动（`batch_curves`）

**没做的（当时就写明了）**
- 光谱处理模块没迁（D-39）
- 功能 tab 仍写死（荧光、散射是数据类型，模块目前只吃光谱矩阵）
- 模块没有沙箱（D-38）

**实测**：拖动 2.2 → 2.4 ms；膜厚松手 50 → 48–55 ms；OT 迁移前后最大差 5e-4 nm；规范报告逐字相同。
**验证**：302 → 330 个测试。
