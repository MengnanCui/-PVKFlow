# HTE Studio

高通量实验数据平台。**本地运行，双击就开，不联网也能用。**

原位吸收光谱矩阵进来，出去的是热力图、干涉条纹、光学膜厚曲线、谱斜率与波段积分，
以及一批样品横着放在一起的对比。数据全在你自己机器上。

**数据处理 → 数据存储 → 构效关系** —— 三层在时间上有先后。当前版本把前两层做扎实，
第三层留好入口和数据形态。

---

## 一、跑起来需要什么

只有一件事：**Python 3.11 或更高版本**。

- Windows：到 [python.org](https://www.python.org/downloads/) 下载安装，
  安装时**务必勾选 "Add python.exe to PATH"**（这一步漏了，双击 `run.bat` 会告诉你）
- macOS / Linux：一般自带，`python3 --version` 看一眼

其余的依赖（FastAPI、numpy、pandas…）**首次启动时自动装**，你不用管。

不需要：Node.js、数据库服务、Docker、管理员权限、联网的模型服务。

### 会占多大

| | 大小 | 说明 |
|---|---|---|
| `.venv/`（Python 依赖） | **约 220 MB** | 一次性，装完不再长 |
| `workspace/`（你的数据） | 约原始数据的 **1.4 倍** | 随导入的数据增长 |

那 220 MB 里 **pandas + numpy 就占了 150 MB**。numpy 是所有数值计算的地基，
没得商量；pandas 用在通用表格解析和 skill 契约的 `ctx.load_table()` 上。

已经砍掉的两项：`pyarrow`（131 MB，批处理长表改用 CSV）和
`uvicorn[standard]` 的额外组件（19 MB，uvloop / watchfiles / websockets 一个都没用到）。
砍之前是 372 MB，砍之后 219 MB —— 都是干净安装实测的数字。

> pyarrow 值不值 131 MB，算一笔账就清楚：一次 40 样品的批处理长表，
> Parquet 0.05 MB / CSV 0.63 MB，省 0.58 MB。要跑两百多次批处理，
> 省下的体积才抵得上它自己的安装体积 —— 而且这个规模下它读写还更慢。
> 以后真要上 DuckDB 做跨表查询时再 `pip install pyarrow` 即可，
> 代码里那条分支一直留着，装了就自动用 Parquet。

## 二、启动

**Windows：双击 `run.bat`。**
**macOS / Linux：`./run.sh`。**

首次启动约一分钟（建虚拟环境 + 装依赖），之后几秒。浏览器会自动打开
`http://127.0.0.1:8765`。

关闭：回到那个黑窗口按 `Ctrl+C`（或者直接关掉窗口）。

几件可能碰到的事：

| 情况 | 会发生什么 |
|---|---|
| 8765 端口被占了 | 自动往后找一个能用的（8766、8767…），地址打印在窗口里 |
| 公司网络装依赖失败 | 窗口里会说清楚，并给出手动安装的命令 |
| `.venv` 坏了（比如系统 Python 升级过） | `run.bat` 会自己重建 |
| 想换端口 / 不自动开浏览器 | `HTE_PORT=9000`、`HTE_NO_BROWSER=1` |

> **只监听 127.0.0.1**，同一个局域网里的别人访问不到。这是刻意的 ——
> 平台没有登录和权限体系，不该暴露在网络上。

## 三、接上你的模型（可选，两分钟）

先说清楚：**不配模型，平台照样完整可用。** 文件识别、导入、解析、热力图、
膜厚计算、批处理对比、导出脚本，全都不需要模型。配了之后多出来的是右上角
那个「AI 助手」：问答、让它帮你筛样品、让它提议跑一次处理。

### 怎么填

**「设置 → 模型」，三个框：**

| 框 | 填什么 | 例子 |
|---|---|---|
| 接口地址（baseUrl） | 你的网关地址，**结尾带 `/v1`**。`http://` 和 `https://` 都收 | `http://你的内网网关/v1` |
| 密钥（apiKey） | 直接粘贴，不用加引号 | `sk-…` |
| 模型名（model id） | 网关文档里那个 id，区分大小写 | `Qwen3.6-27B` |

点「保存并启用」就能用了。旁边还有个「测试」按钮，会真的发一句话过去，
把延迟和回复打出来 —— 连不上的时候先点它。

改地址或换模型时**密钥可以留空**，表示「不改，继续用存着的那个」。
（界面上只显示打码后的密钥，你手里未必还有原文。）
**模型也可以先留空** —— 不少自建网关没有 `/models` 接口，拉不到列表；
先把地址和密钥存下来，之后在「模型」那一栏手打一个模型名再保存就能用。

地址栏下面那个下拉是候选地址。里面预置了几个公共服务商，
点「存成候选」可以把你自己的网关加进去 —— 填一次，以后从下拉里直接选。
**你存的候选和密钥一样只在本机**：都写在 `workspace/config/providers.json`，
那个目录在 `.gitignore` 里，不会被提交进仓库。

要配多个网关、多个模型？下面「高级：直接粘 JSON」展开，结构是：

```json
{
  "providers": {
    "本地 vLLM": {
      "baseUrl": "http://你的主机/v1",
      "api": "openai-completions",
      "apiKey": "sk-...",
      "compat": { "supportsDeveloperRole": false },
      "models": [{ "id": "Qwen3.6-27B", "name": "Qwen 3.6 27B", "input": ["text", "image"] }]
    }
  }
}
```

任何 **OpenAI 兼容**的服务都行：vLLM、各家网关、OpenAI 本身、本地 Ollama
（`http://localhost:11434/v1`）。

### 密钥存在哪、安不安全

写进 `workspace/config/providers.json`。这个文件：

- 在 `.gitignore` 里（`workspace/` 整个目录 + `**/providers.json` 双重保险），
  **永远不会被 git 提交**
- 任何接口返回时都只给打码后的前后几位（形如 `sk-abc…7890`），原文不出你的机器
- 只用来向你填的那个 baseUrl 发请求，不发给别处

### 连不上的时候

点「测试」，它会如实说是哪一步出的问题：

- `连接 xxx 失败` —— 地址不对，或者网络不通
- `返回 401 / 403` —— 密钥不对
- `返回的不是 JSON（可能是代理或登录页拦截了请求）` —— 公司网络最常见的一种：
  代理或 SSO 把请求截下来回了个登录页，状态码还是 200。先在浏览器里打开那个
  baseUrl 看看

## 四、数据存在哪

**全部在 `workspace/` 这一个目录里。** 整个拷走就能换机器，删掉就等于恢复出厂。

```
workspace/
├─ hte.db            SQLite：样品、测量、分析运行、关键结果、AI 对话
├─ raw/              复制进来的原始文件（按 sha256 内容寻址，同内容自动去重）
├─ derived/          缩略图、skill 产出的图
├─ tables/           批处理的曲线长表（几万行数值走这儿，不进 SQLite）。
│                    默认 CSV；装了 pyarrow 就自动改用 Parquet
├─ cache/            解析缓存（.npz）。删了只是下次慢约 1 秒
├─ config/           providers.json —— 你的模型密钥
├─ skills/           你自己丢进来的处理算法
└─ logs/  tmp/
```

**想放到别的盘**（比如 D 盘或网络盘）：设环境变量 `HTE_WORKSPACE=D:\HTE`，
或者在 `run.bat` 第一行后面加 `set HTE_WORKSPACE=D:\HTE`。

**备份**：把 `workspace/` 整个目录复制走就是完整备份，没有别的地方藏东西。
真正不可再生的是 `hte.db` 和 `raw/`；`cache/`、`derived/`、`tables/` 都能重算。

**大概占多少**：一次导入 3 个样品（每个 `Data.csv` 约 2.2 MB）之后，
`workspace/` 是 9.3 MB —— 其中 `raw/` 6.7 MB（原始文件）、`cache/` 1.7 MB（解析缓存）。
所以粗略估：**原始数据体积的 1.4 倍左右**。

数据本身通常不是占地方的大头 —— `.venv` 那 220 MB 才是。
两者是分开的：删 `workspace/` 清数据，删 `.venv/` 清依赖（下次启动会重装）。

缓存有上限（默认 8 GB），超了自动淘汰最久没用的。「设置 → 工作区」能看到
当前占用，也能一键清空。

### 导入时文件怎么落地

| 类型 | 怎么处理 | 为什么 |
|---|---|---|
| 文本类（csv / txt / dat / json / xlsx …） | **复制**进 `workspace/raw/` | 小、易丢、经常被人手改。复制一份才谈得上可复现 |
| 图像类（png / jpg / tif …） | **不复制**，只登记路径 + 哈希，另生成缩略图 | 动辄几百 MB，搬一遍不划算 |

代价说清楚：引用型文件被移动或改名后会断链 —— 界面上会标成「丢失」，
**不会静默当作正常**。（主动全量巡检的接口有了（`POST /api/files/verify`），
按钮还没做。）

拖拽上传是个例外：浏览器出于安全不给真实路径，所以那条通道**一律复制**。

## 五、五分钟走一遍

### 1. 导入

「数据处理 → 导入数据」，选**主文件夹**（就是装着一堆子文件夹的那个）。

平台认真实仪器的目录结构：

```
总文件夹/
  ZG0013_2026072918354709_Mode5_202607291932_SPS100/
      Data.csv   Heatmap_Absorption.png   Options.json   PostProcessState.json
  ZG0014_2026072918250401_Mode5_202607291833_SPS100/
  ZG0014_2026072918250402_Mode5_202607291835_SPS100/
```

**一个子文件夹 = 一次测量 = 一个样品。** 所以上面 ZG0014 的两次是**两个样品**，
不是一个样品的两条曲线 —— 做统计时别把它们当重复样平均掉。

文件夹名里的信息会被拆出来用：`ZG0013` 进「样品号」这一维，
`2026072918354709` 变成测量时间（按时间筛选靠它）。

`Data.csv` 是制表符分隔、有两个数据块的格式，平台**只取 `Absorption Wavelength` 那块**
（前面 `Origin Wavelength` 是原始 PD 计数，不是你要的）。

导入前先给预览：哪些会被复制、每个文件夹解析出的样品名和时间。确认后才写入。

没有真实数据想先试试？`python sample_data/make_insitu.py` 生成三个样例，
再导入 `sample_data/insitu/`。

### 2. 挑样品

左边三个筛选维度（刻意只留三个）：**测量时间 / 样品号 / 文件夹**。
时间那栏可以直接敲，也可以点「选择…」用日历选到分钟。

中间列表里选样品：

- **点一行** = 选中
- **按住拖** = 一路刷过去（拖到列表边缘会自动滚）
- **shift + 点** = 选中间一整段
- **双击**或行尾的「打开」= 进这个样品的详情页

> 一次选择在内部是一条**筛选式**，不是一串 ID。所以它能存下来、能分享、
> 新导入的样品会自动进来。

### 3. 单个样品看细节

点进去有三个模块：

| 模块 | 内容 |
|---|---|
| **光谱处理** | 全波长强度热力图（彩虹色标）+ 不同时刻的光谱叠加（浅→深 = 早→晚），左右并排 |
| **膜厚处理** | 四宫格：上排全波段条纹图 + OT 曲线，下排指定波段（默认 775–1120 nm）的同两张 |
| **特殊处理** | 谱斜率 vs 时间 ｜ 波段积分 vs 时间，**拖滑块实时更新** |

每张图右上角有「下载 ▾」：下载图片（2× PNG）或下载数据（CSV）。

膜厚按 `fringe-optical-thickness` 冻结规范实现，四宫格下面挂着规范
§5 要求的完整报告（块 A–D，一个字不省）。**判据只打标志，绝不修改数值** ——
条纹数不够时你看到的是「算出来是多少 + 为什么不该信」，不是一个被悄悄改过的数。

### 4. 批处理与对比

在样品列表选一批 → 「批处理选中的 N 个」。跑完直接落到对比页：
谱斜率和波段积分左右并排，一条曲线一个样品。超过 60 条自动降级成分位数带
（并在图注里写明降级了，不偷偷少画）。

每次批处理都留在**「分析 → 对比历史」**里，随时点回去。
还能「导出脚本」，拿到一份 `plot.py` + `data.csv`，在你自己的 Python 里重画。

### 5. AI 助手（配了模型才有）

右上角「AI 助手」，或 `Ctrl/Cmd + K`。

- 抽屉可以拖左边缘改宽度、可以全屏、有对话历史
- 底部有个**数据范围**选择器：`选中的 N 个` / `全部命中的 N 个`。
  勾了东西默认前者，没勾默认后者
- 它能看到的是**汇总统计和标量**，看不到原始光谱矩阵（一个样品 211 帧 × 1028 波长，
  带上去就把上下文撑爆了）。样品超过 40 个时只给汇总，并会提议先收窄范围
- 它想帮你筛样品或跑处理时，给的是一张**你能改、能拒绝的卡片**，
  点了才算数 —— **模型写的操作不会自动执行**
- 有用的回答可以「📌 钉住」到某次对比上，之后在对比页和对比历史里都看得见

## 六、加一个你自己的处理算法

把目录丢进 `workspace/skills/`，点「重载 Skill」：

```python
from app.skills.base import Skill, SkillSpec, ParamSpec, OutputSpec, FileMatch, SkillResult, Metric

class MyThickness(Skill):
    spec = SkillSpec(
        id="thickness.profilometer", name="台阶仪膜厚",
        category="thickness", version="1.0.0",
        accepts=FileMatch(extensions=[".csv"]),
        params=[ParamSpec("baseline", "基线区间", "range", default=[0, 10], unit="%")],
        outputs=[OutputSpec("thickness", "膜厚", unit="nm")],
    )

    def run(self, ctx):
        df, _ = ctx.load_table()          # 编码/分隔符/仪器抬头已经嗅探好
        return SkillResult(metrics=[Metric("thickness", my_algorithm(df), unit="nm")])

SKILL = MyThickness()
```

**参数表单、结果卡片、图表全部自动生成，不用碰任何前端代码。**
完整说明：[`docs/SKILL_CONTRACT.md`](docs/SKILL_CONTRACT.md)

## 七、目录与开发

```
run.bat / run.sh     一键启动
app/                 后端（FastAPI + SQLite + Parquet，无 ORM）
web/                 前端（原生 ES Module，零构建）
tools/               开发用小工具（见下）
docs/                架构、数据模型、Skill 契约
sample_data/         可以直接拿来试的样例数据
workspace/           你的全部数据（gitignore）
```

```bash
./run.sh                                # 起服务
.venv/bin/python -m pytest -q           # 跑测试
```

前端改完刷新页面即可，没有构建步骤。

### 把界面烤成一个 .html

```bash
.venv/bin/python tools/bake_offline.py              # 烤到 dist/hte-studio.offline.html
.venv/bin/python tools/bake_offline.py --skip-record  # 只改了前端代码时，复用上次录的数据，几秒钟
```

产出**一个自包含的 html**：CSS / 字体 / JS 全部内联，后端每个接口的真实响应
也录在里面。双击就开，不用装 Python、不用起服务 —— 想在没环境的机器上看一眼界面、
想把它发给别人指指点点、想留一份「这一版长什么样」，都靠它。
图能悬停、滑块能拖、ⓘ 能点开、明暗能切、页面能来回走。

重跑批处理 / 存模型配置 / 导入文件 / AI 对话这几件事真的需要后端，
离线版里点了会**明说做不到**，不是点了没反应。

录接口要 Playwright（`npm i playwright`，或者用 `PLAYWRIGHT_DIR=` 指到已经装了的目录）。
产物在 `dist/`，不进仓库 —— 它是工作区数据的快照。

- [架构](docs/ARCHITECTURE.md) —— 模块划分与设计原则
- [数据模型](docs/DATA_MODEL.md) —— 为什么 `key_result` 是长表
- [Skill 契约](docs/SKILL_CONTRACT.md) —— 怎么接入你的算法

## 八、现在不做什么

说清楚边界，省得你以为是坏了：

- **构效关系页**只有入口和数据形态，实际的 X/Y 映射与相关性分析还没做
- 「荧光 & 荧光」「荧光 & 散射」「QFLS」三个功能标着「规划中」，点不动
- 不会静默监听目录、自动跑 skill —— 所有处理都要你点一下
- 没有打包成单个 exe（需要先装 Python）
- 没有登录和权限体系，所以只监听本机
- 模型写的代码**不会被执行**。它只能输出筛选式和配方，由界面渲染成卡片，
  你点了才生效
